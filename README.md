# 研途打卡

考研打卡小站：每天三句名人名言、打卡记录、日历补卡、考试倒计时、时间扇形图。

纯前端，无后端、无依赖，打卡数据只存在浏览器本地。

## 功能

- **每天三句**：681 条名言，按轮次洗牌，227 天一轮，轮内不重复
- **打卡**：任务、时长、专注度、备注，一天可以记多条
- **预设项目**：把「英语单词」这类常用项目存成快捷按钮，点一下自动填好任务名
- **计时**：选中项目后开始计时，自动进入全屏专注界面；结束时按分钟取整，自动记一条；也可以直接手动填时长
- **日历**：补记过去的日子，也能修改和删除
- **时间去向**：按选中日期画扇形图，可前后翻日期，并和前一天比总时长
- **资料区**：四个常用考研站点的入口
- 数据本地存储，不上传

## 本地运行

需要 Python 3.9+：

```bash
python tools/serve.py
```

打开 http://127.0.0.1:8788/ ，换端口加 `--port 9000`。

> 直接双击 `index.html` 也能用，但浏览器会拦住 `quotes.json` 的读取，页面会退回内置的 9 句兜底。

## 每天三句怎么来的

`quotes.json` 里有 **681 条**。前端按「从 2026-01-01 起的第几天」分组，每 227 天为一轮：

- 每轮开始时把整池重新打乱（种子由轮次决定，同一天结果固定）
- 一轮内每天取连续三条，227 天正好用完 681 条，整轮不重复
- 一轮走完自动进入下一轮，重新洗牌

如果当天拿不到 `quotes.json`，先用 9 句内置兜底，再从 `localStorage` 恢复上一次成功拿到的池子。

## 计时规则

- 不满 30 秒的零头舍去，满 30 秒进 1 分钟
- 例：50 秒记 1 分钟，90 秒记 2 分钟，29 秒不记录
- 开始计时会自动打开沉浸界面；点「返回页面」计时继续，点时间数字可以再进去
- 刷新页面会丢掉正在进行的计时，项目本身不受影响

## 扩充名言

1. 在 `data/` 里加 `quotes-04.json`（或任意 `quotes-xx.json`）：

   ```json
   [
     { "t": "千里之行，始于足下。", "a": "老子《道德经》" }
   ]
   ```

   - `t` 是句子，`a` 是作者或出处，都不能空
   - 分片按文件名排序读取，重复的句子自动丢掉

2. 重新合并：

   ```bash
   npm run build
   ```

3. 刷新页面。改完 `app.js` 记得把 `index.html` 里的 `app.js?v=23` 版本号往上加。

条数保持 3 的倍数，每轮才能完整覆盖。现在 681 条 = 227 天 × 3。

## 测试

需要 Node 18+：

```bash
npm test
```

用最小 DOM 跑一遍 `app.js`，检查提交后界面是否立即更新，以及旧页面缺少新节点时不会崩。

## 部署到 GitHub Pages

1. 推到 GitHub
2. 仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`
3. 等一分钟，访问 `https://<用户名>.github.io/<仓库名>/`

不需要构建步骤，`quotes.json` 用的是相对路径。

## 名言来源与版权

- 中国古典部分以通行本原文为准，出处写到篇名。
- 外国名言是通行中译，译者不止一位，不逐字对应某本译本。
- 标「（传）」的是转述或难确证原话的句子；标「（意译）」的是按原意重写的中文。
- 内容仅供学习交流。如权利人认为有不妥，联系删除。
- 代码以 MIT 协议开源。

## 已知限制

- 打卡数据是单设备本地存储，换设备不同步。
- 页面除了读同目录的 `quotes.json`，没有其他联网请求。
- 未在旧版浏览器和真机移动端上验证。
